DEMO 2E - ATTACK 4: stacked query to destroy data
========================================================================

* VULNERABLE version
  Input typed into the search box: "x'; DROP TABLE students; -- -"
  SQL sent to the server:
    SELECT student_id, first_name, last_name, programme FROM students WHERE last_name = 'x'; DROP TABLE students; -- -' AND programme = 'BIT'
  Query FAILED: (1064) You have an error in your SQL syntax; check the manual that corresponds to your MariaDB server version for the right syntax to use near 'DROP TABLE students; -- -' AND programme = 'BIT'' at line 1
  (Blocked twice over: the driver refuses multiple statements and
   app_service has no DROP privilege.)

Summary: parameterised queries stop injection at the source; least
privilege limits the damage if a mistake slips through.

  hash 2: pbkdf2_sha256$600000$24e220b04f8048080e568ee92859ca39$4a841c...
  identical? False  (so one cracked hash does not reveal other users)

Login attempts:
  correct username and password            -> logged in as registrar

  unknown username                         -> REJECTED
